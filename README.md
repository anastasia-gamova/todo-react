# Список задач (To-Do List) — версия на React

Небольшое веб-приложение «Список задач»: можно добавлять задачи, отмечать их
выполненными, удалять и редактировать. Список сохраняется в браузере, поэтому
после перезагрузки страницы все задачи остаются на месте.

Это **вторая версия** тестового задания — то же приложение, что и
[версия на Vue](https://github.com/anastasia-gamova/todo-vue), но написанное
на React. Функционал и дизайн полностью совпадают, отличается только фреймворк.

## Возможности

- ➕ Добавление задачи — по нажатию Enter и по кнопке «Добавить». Пустую задачу
  или задачу из одних пробелов добавить нельзя.
- ✅ Отметка задачи выполненной (свой круглый чекбокс с анимированной галочкой).
- 🗑️ Удаление задачи.
- ✏️ Редактирование по двойному клику или по кнопке-карандашу: **Enter** —
  сохранить, **Esc** — отменить. Если очистить текст и сохранить, задача удаляется.
- 💾 Сохранение в `localStorage` — данные не теряются после перезагрузки.
  Если в хранилище попали «битые» данные, приложение не падает, а начинает
  с пустого списка.
- 🔎 Фильтры «Все / Активные / Выполненные» наверху; под списком слева счётчик
  оставшихся задач с правильным склонением, справа — кнопка «Удалить выполненные».
- 📭 Понятное пустое состояние, когда задач нет.
- 🌗 Тёмная тема по настройке системы плюс ручной переключатель; выбор
  запоминается в `localStorage`, цвета заданы через CSS-переменные.
- 🎬 Анимации появления и удаления задач и смены фильтра — с учётом системной
  настройки «меньше движения» (`prefers-reduced-motion`).
- 📱 Адаптивная вёрстка — удобно и на телефоне (проверено на 375px), и на компьютере.
- ♿ Доступность: подписи у полей и кнопок, работа с клавиатуры.

## Структура проекта

```
src/
  components/           # компоненты интерфейса
    TaskInput.tsx       # поле добавления задачи
    TaskItem.tsx        # одна задача (просмотр + редактирование)
    TaskList.tsx        # список задач
    TaskFilters.tsx     # фильтры «Все / Активные / Выполненные»
    TaskFooter.tsx      # счётчик и «удалить выполненные»
    ThemeToggle.tsx     # переключатель темы
  hooks/
    useTasks.ts         # вся логика работы с задачами (отдельно от компонентов)
    useTheme.ts         # логика темы
    useAnimatedList.ts  # анимация появления/удаления без сторонних библиотек
  styles/
    main.css            # стили
  types.ts              # типы Task и Filter
  App.tsx               # сборка интерфейса
  main.tsx              # точка входа
tests/
  useTasks.test.ts      # тесты логики (Vitest)
  App.test.tsx          # тесты интерфейса (React Testing Library)
  setup.ts              # окружение для тестов (in-memory localStorage, matchMedia)
```

Вся логика задач вынесена в хук `src/hooks/useTasks.ts` и не зависит от
компонентов — это упрощает тестирование и переиспользование.

## Как запустить локально

Нужен установленный [Node.js](https://nodejs.org/) (версия 20 или новее).

```bash
# установить зависимости
npm install

# запустить дев-сервер (адрес появится в консоли, обычно http://localhost:5173)
npm run dev
```

## Как запустить тесты

```bash
# прогнать тесты один раз
npm run test

# тесты в режиме наблюдения (перезапуск при изменениях)
npm run test:watch
```

## Другие команды

```bash
npm run build   # сборка продакшн-версии в папку dist
npm run preview # локальный просмотр собранной версии
```

(линт, тесты и сборку). Если что-то не проходит — коммит не создаётся.

## Чем React отличается от Vue на примере этого проекта

Коротко — три вещи, которые делают одно и то же, но по-разному.

### 1. Как хранится состояние

- **Vue.** Состояние — это «реактивные ссылки»: `const tasks = ref([])`.
  Меняем прямо на месте — `tasks.value.push(...)` или
  `task.completed = !task.completed`, — а Vue сам замечает изменение и
  перерисовывает нужное.
- **React.** Состояние живёт в хуке `useState`, а менять его можно только через
  функцию-сеттер и обязательно **новым** объектом/массивом (иммутабельно):
  `setTasks(prev => [...prev, newTask])`, для переключения —
  `prev.map(t => t.id === id ? { ...t, completed: !t.completed } : t)`.
  React сравнивает старое и новое значение и перерисовывает компонент.

Главная разница: во Vue мы **мутируем** данные, в React — **создаём новые**.

### 2. Как пересчитываются фильтры и счётчики

- **Vue.** Используется `computed`: `const filteredTasks = computed(() => ...)`.
  Vue сам отслеживает, от чего зависит вычисление, и пересчитывает только когда
  эти данные поменялись.
- **React.** Используется `useMemo`, и зависимости нужно перечислить руками:
  `useMemo(() => ..., [tasks, filter])`. React пересчитает значение, только если
  изменилось что-то из списка в квадратных скобках.

Главная разница: во Vue зависимости вычисляются автоматически, в React их
указываешь сам.

### 3. Как сохраняется в localStorage

- **Vue.** Через `watch(tasks, () => save(...), { deep: true })` — «следим за
  списком и при любом изменении сохраняем».
- **React.** Через `useEffect(() => save(...), [tasks])` — «побочный эффект,
  который запускается после рендера, когда изменился `tasks`».

Идея одна (сохранить при изменении), но во Vue это `watch`, а в React — `useEffect`
со списком зависимостей.

### Ещё пара мелочей

- **Шаблон vs JSX.** Во Vue разметка — это отдельный `<template>` с директивами
  `v-if`, `v-for`, `@click`. В React разметка пишется прямо в JavaScript (JSX):
  условие — это тернарный оператор `{isEmpty ? ... : ...}`, список — `{items.map(...)}`,
  обработчик — `onClick={...}`.
- **Передача данных.** Во Vue — `props` вниз и `emit('событие')` вверх. В React
  вниз передаются и данные, и функции-колбэки (`onToggle`, `onRemove`), а «вверх»
  ребёнок сообщает, просто вызвав переданную функцию.
- **Анимации списка.** Во Vue есть встроенный `<TransitionGroup>`. В React такого
  из коробки нет, поэтому анимация появления/удаления сделана своим небольшим
  хуком `useAnimatedList` плюс CSS — без сторонних библиотек.
